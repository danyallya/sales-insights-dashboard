# Project working rules
- Treat Aurelia as a commerce revenue product for independent merchants. Keep the visual language editorial, precise and restrained.
- Before every daily session, read this file, BACKLOG.md, the current Git status and prior changes. Review existing UI and logic for defects before starting today's ticket.
- Every session includes code review of prior work, relevant test writing or updates, today's implementation, documentation updates, debugging and a final review. Run tests, typecheck and build when dependencies are installed; fix regressions before committing.
- Keep chart values and metric definitions coherent. Clearly identify sample figures until a connected source exists.
- Preserve responsive phone, tablet and desktop layouts, both themes, keyboard access and text alternatives for charts.
- Use React, TypeScript, Vite, Tremor, Tailwind utilities and React Icons. Keep data and components typed.
- Update BACKLOG.md after each session: record completion, add discovered work and leave tomorrow's scope explicit.
- Keep .npmrc local and untracked. Never commit credentials, environment files, merchant data or build output. Do not force-push or rewrite Git history.
- Work only inside this project unless the user expands scope. Use descriptive day branches and meaningful commits after checks pass.

## Delivery from Day 02

- Read and follow [DELIVERY-POLICY.md](DELIVERY-POLICY.md). Finish Aurelia, including its own PR panel review and merge or a recorded external blocker, before starting the next portfolio project. No parallel project work.
- Derive commit count, content and wording from Aurelia's real metric, chart and interaction changes; do not copy a fixed commit pattern from other projects.
- Push a repository-specific branch, review the latest head and checks in GitHub, and merge through its PR panel. Required independent approvals remain external gates; do not substitute self-review for them.

## Community contribution goals — effective Day 02

- Read [CONTRIBUTING.md](CONTRIBUTING.md) at startup. Integrate its Aurelia examples and real collaboration opportunities into existing daily/weekly/documentation work. Preserve sequential delivery, product-specific commits and every PR gate.
- Recognition is account-wide and externally awarded. No activity quotas, fake coauthors, manufactured issues, star exchanges or review shortcuts; record actual evidence and uncertainty.
